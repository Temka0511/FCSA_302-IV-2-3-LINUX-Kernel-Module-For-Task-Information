\section*{Хураангуй}
\addcontentsline{toc}{section}{Хураангуй}
Linux системийн процесс, thread-ийн мэдээллийг kernel module-оор уншиж, холбоосыг графаар харуулах TaskGraph програм хэрэгжүүлэв. Модуль нь PID, төлөв, нэрийг LINEAR болон DFS дарааллаар хэвлэж, \code{/proc/taskgraph} файлаар шинэ хэмжилт өгнө. UI-аас дэд мод сонгох, thread шүүх, дарааллаар үзэх, мэдээлэл хадгалах боломжтой. Python-ийн 28, бодит Linux kernel-ийн 17 шалгалт нийт 45/45 тэнцсэн. Туршилтын 7 task-ийн нэр, төлөв, parent болон thread group нь procps-ийн гаралттай таарсан.

\section{Удиртгал}
Зорилго нь Linux-ийн процессын бүтэц, эцэг-хүүхэд холбоо болон DFS аргыг бодит өгөгдөл дээр судлах юм. Процесс үүсэх, зогсох, дуусах өөрчлөлтийг граф, хүснэгтээр ажиглана. Хэрэгжилт нь C kernel module, Python parser, Tkinter UI гэсэн гурван хэсэгтэй.

\section{Онолын үндэс}
Linux-ийн \code{task\_struct} бүтэц нь нэг task-ийн PID, төлөв, нэр болон бусад task-тай холбогдох жагсаалтын холбоосыг агуулдаг. Процесс ба thread хоёулаа энэ бүтцээр дүрслэгддэг ч бүлэгт харьяалагдах байдлаараа ялгаатай. \textbf{PID} нь тухайн task-ийн дугаар, \textbf{TGID} нь thread group-ийн дугаар юм. Process leader-ийн PID ба TGID ижил; нэмэлт thread-ийн PID өөр боловч TGID нь leader-ийн PID-тай тэнцэнэ.

\textbf{PPID} нь эцэг процессын дугаарыг илэрхийлнэ. Гэвч thread-ийн бүлгийн гишүүнчлэл нь эцэг-хүүхдийн холбоотой адил биш. Иймээс графт process-ийг PPID руу нь, нэмэлт thread-ийг TGID руу нь холбоно. Бодит PPID-г тусдаа баганад хадгалснаар дүрслэхэд хэрэглэсэн \code{parent} утгыг үйлдлийн системийн эцэг процессын дугаартай андуурахгүй.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\textwidth]{figures/task_tree.pdf}
\caption{Бодит created snapshot-ийн 7 task: бүтэн сум нь эцэг-хүүхэд, тасархай сум нь thread гишүүнчлэл.}\label{fig:tree}
\end{figure}

Зураг~\ref{fig:tree}-т PID 90 нь үндсэн процесс, PID 91, 92 нь түүний хүүхэд, PID 93, 94 нь дараагийн үеийн хүүхэд байна. PID 95, 96 нь TGID 90-той thread-үүд бөгөөд тусдаа хүүхэд процесс гэж тооцогдохгүй. \textbf{LINEAR} жагсаалт нь process leader-уудыг kernel-ийн process жагсаалтаар уншина. \textbf{DFS} нь эцгийг үзсэний дараа хүүхдийн дэд модыг бүрэн туулж, дараагийн ах дүү рүү шилжинэ. Манай өргөтгөл leader-ийн дараа түүний нэмэлт thread-үүдийг оруулдаг тул зурагт буй DFS дараалал 90, 95, 96, 91, 93, 92, 94 болсон.

Төлөвийн тэмдэг нь хэмжилтийн агшныг илэрхийлнэ: R --- ажиллаж байгаа эсвэл бэлэн; S --- унтаж байгаа; I --- idle kernel thread; D --- тасалдуулж болохгүй хүлээлт; T/t --- зогсоосон; Z/X --- zombie/dead. Дараагийн хэмжилтэд төлөв өөрчлөгдөж болно.

\section{Системийн зохиомж}
Системийг Linux цөмөөс мэдээлэл авах хэсэг, тэр мэдээллийг шалгаж дүрслэх хэрэглэгчийн хэсэг гэж зохион байгуулсан. Kernel module нь бодит task-ийн бүтэцтэй ажиллаж, Python програм нь module-ийн гаргасан өгөгдлийг уншина. Ингэснээр граф зурах, шүүлт хэрэглэх болон файл хадгалах үйлдэл kernel-ийн task жагсаалтыг өөрчлөхгүй.

\begin{figure}[H]
\centering

Зураг~\ref{fig:architecture}-ийн дээд хэсэгт \code{taskgraph.c} нь \code{task\_struct}-уудаас өгөгдөл хуулж, LINEAR болон DFS дарааллыг гаргана. Module ачаалах үеийн жагсаалт kernel log-д хэвлэгддэг бол \code{/proc/taskgraph} нь файл нээх бүрд шинэ snapshot өгдөг интерфэйс юм. Иймээс эхний log ба дараа нь уншсан proc файл өөр агшны хэмжилт байж болно.

Доод хэсгийн \code{model.py} нь TSV өгөгдлийг parse хийж, шалгагдсан \code{Snapshot} объект үүсгэнэ. \code{gui.py} ба \code{cli.py} энэ ижил загварыг ашигладаг тул график болон командын мөрийн хувилбар тус тусдаа өгөгдөл тайлбарлах шаардлагагүй. TSV экспорт нь бүтэн snapshot-ийг хадгалж, дараа нь файл импортлох замаар ижил хэмжилтийг дахин шалгах боломж олгоно.

\section{Хэрэгжилт}
\code{tg\_capture()} нь мөр, стек, индексийн санах ойг урьдчилан хуваарилна. \code{stop\_machine()} дотор CPU-уудыг түр саатуулж, процессын холбоос өөрчлөгдөхгүй үед мэдээллийг хуулна. Энэ нь module-д export хийгдээгүй \code{tasklist\_lock}-ийг шууд ашиглахгүйгээр жагсаалтыг хамгаална \cite{stop}. RCU уншилтын хамгаалалтыг мөн хэрэглэнэ \cite{rcu}.\par
\code{tg\_walk()} нь \code{init\_task.children}-аас эхэлж, \code{sibling} холбоосоор хүүхдүүдийг гүнээр туулна. Thread бүрийн children жагсаалтыг шалгадаг тул process leader бус thread-ийн үүсгэсэн хүүхэд орхигдохгүй. Thread-үүдийг TGID-ийн гишүүнчлэлээр нэмнэ. Callback дотор санах ой хуваарилах, хэвлэх, унтуулах үйлдэл хийхгүй; модулийн entry point-оос LINEAR, DFS үр дүнг kernel log-д хэвлэнэ.
\code{seq\_file} нь нэг нээлттэй файлаас хэсэгчлэн уншихад ижил snapshot ашиглана \cite{seq}. Дахин нээх бүр шинэ өгөгдөл авна. \code{max\_tasks} нь 16--16384, анхны утга 4096. Хязгаар хүрвэл \code{truncated=1} гэж мэдээлнэ. Parser нь формат, PID давхардал, дараалал, төлөв болон оролтын хэмжээг шалгана.

GitHub-ийн main салбарт эх код, тест, баримтыг commit-оор хадгалсан. Түүхэнд хэрэгжилт, Ubuntu заавар, багийн мэдээлэл, тайлангийн засварууд тусдаа бүртгэлтэй. Хувилбар: v1.1.3-bd1.\par

\section{Хэлэлцүүлэг}
Граф болон хүснэгт нь kernel-ийн PID, parent, төлөвийн мэдээлэлтэй тохирч байв. Тестээр process-thread ялгалт, DFS дараалал, STOP төлөв, буруу параметр болон модулийн цэвэрлэгээг шалгасан.
\code{stop\_machine()} ашигласнаар бүтэц өөрчлөгдөхгүй үед children/sibling холбоосыг уншина. Гэхдээ CPU-уудыг түр саатуулдаг тул энэ хэрэгжилт сургалтын Linux VM-д зориулагдсан; бага latency шаардсан системд тохиромжгүй. Snapshot хооронд PID, төлөв өөрчлөгдөнө. Хэмжээний хязгаараас болж parent багтаагүй бол root-д холбоод \code{orphan=1} гэж тэмдэглэнэ. \code{comm} нь богино нэр; бүтэн командын мөр биш. Том системд \code{max\_tasks}-ийг өсгөнө.
Kernel ажиллагааг QEMU initramfs орчинд шалгасан. Тайлангийн UI зураг нь тэндээс авсан snapshot-ийн дүрслэл юм. Хадгалсан snapshot нь өмнөх хэмжилтийг давтан үзэхэд зориулагдсан; бодит Linux хэмжилтийг \code{--kernel} горимоор ажиллуулна.

\section{Дүгнэлт}
Процессын жагсаалтыг LINEAR болон DFS аргаар гаргах kernel module, task graph UI, snapshot хадгалах болон дахин үзэх боломжийг хэрэгжүүлэв. Нийт 45 автомат шалгалт тэнцсэн. Номын хоёр traversal болон procps-тэй харьцуулах шаардлагыг туршилтын нотолгоогоор баталгаажуулсан. Төслөөр Linux-ийн task бүтэц, process-thread холбоо, төлөв болон DFS-ийг бодит өгөгдөлтэй холбон судалсан.
