\section{Зорилго ба дэмжих орчин}
TaskGraph нь Linux-ийн process, thread-ийн холбоос, төлөвийг граф болон хүснэгтээр харуулна. Цөмийн модуль нь ажиллаж байгаа task-уудын мэдээллийг цуглуулж, интерфэйс нь тэдгээрийн эцэг-хүүхэд холбоо болон төлөвийг үзүүлнэ.
\begin{table}[H]
\centering\small
\begin{tabularx}{\textwidth}{@{}P{3.2cm}Y@{}}\toprule
Горим & Шаардлагатай орчин \\\midrule
Linux UI & Python 3, \code{python3-tk}; \code{run.sh}. \\
Бодит module & Ubuntu 24.04 LTS, GCC/Make, ажиллаж буй kernel-ийн headers. Туршсан target: Linux 6.8.0-31. \\
\end{tabularx}
\end{table}

\section{Суулгах ба ажиллуулах}
\subsection{Ubuntu дээр module ажиллуулах}
Ubuntu Terminal-д dependency суулгаад төслийн хавтас руу орно:
\begin{lstlisting}
sudo apt update
sudo apt install -y build-essential \
  linux-headers-$(uname -r) python3 python3-tk git
git clone https://github.com/Temka0511/FCSA_302-IV-2-3-LINUX-Kernel-Module-For-Task-Information.git taskgraph
cd taskgraph
bash scripts/check_env.sh
make -C src/kernel
sudo insmod src/kernel/taskgraph.ko \
  max_tasks=4096 log_on_load=1
bash run.sh --kernel
\end{lstlisting}
Командуудыг дээрх дарааллаар ажиллуулна. Төсөл өмнө нь татагдсан бол \code{cd \textasciitilde/taskgraph}, дараа нь \code{git pull --ff-only} ажиллуулж шинэчилнэ. Дараагийн бүх командыг төслийн хавтас дотроос ажиллуулна.
\code{make} нь модулийг хөрвүүлж, \code{insmod} нь цөмд ачаална. \code{bash run.sh --kernel} нь интерфэйсийг нээнэ; эх үүсвэр \textbf{KERNEL} байна. UI-г энгийн хэрэглэгчээр ажиллуулна. Модуль ачаалах, буулгахад sudo хэрэгтэй. Дуусгаад \code{sudo rmmod taskgraph} командаар буулгана.
\textbf{Параметр:} \code{max\_tasks=16..16384}, анхны утга 4096; \code{log\_on\_load=1} нь LINEAR/DFS log хэвлэнэ. Өөр kernel ашиглавал өөрийн headers-тай дахин build хийнэ.

\section{Ашиглах жишээ}
\subsection{Жишээ 1: бэлэн модыг судлах}
\begin{enumerate}
\item Ubuntu Terminal-д дараах командыг ажиллуулж, Reset дарна.
\begin{lstlisting}
bash run.sh --source examples/small_tree.tsv
\end{lstlisting}
\item DFS сонгож Тоглуулах дарна. Дараалал: 0, 1, 10, 11, 20, 21, 2.
\item Root PID=10 оруулаад Хэрэглэх дарна. 10, 11, 20, 21 гэсэн 4 task харагдана.
\item Threads-ийн чагтыг авахад 11 worker нуугдана.
\end{enumerate}
\subsection{Жишээ 2: kernel-ийн хадгалсан хэмжилт}
Файл нээхээр \code{docs/evidence/created.tsv} сонгож, Root PID=90 оруулна. 7 task бүхий мод гарна. Дараа нь \code{stopped.tsv} нээхэд root-ийн төлөв T болж шарласан байна. \code{after.tsv} нээхээс өмнө Root PID-г цэвэрлэнэ: workload аль хэдийн дууссан тул PID 90 байхгүй.
File горимын авто шинэчлэлт нь ижил файлыг дахин уншина; бодит процессын шинэ өөрчлөлтийг хэмжихгүй.

\clearpage
\subsection{Жишээ 3: бодит Linux процессын мод}
Module болон UI-г kernel горимд ажиллуулсны дараа өөр Terminal нээж, \code{cd \textasciitilde/taskgraph} командаар төслийн хавтас руу орно:
\begin{lstlisting}
export PYTHONPATH="$PWD/src"
python3 -m taskgraph.workload \
  --depth 2 --fanout 2 --seconds 45
\end{lstlisting}
ROOT\_PID мөрийн дугаарыг UI-д оруулж, Шинэчлэх, Хэрэглэх дарна. Энэ workload нь 1+2+4=7 process үүсгэнэ. Авто шинэчлэлтээр хугацаа дуусахад task-ууд алга болохыг ажиглана. Root өөрөө дуусвал талбарыг цэвэрлэнэ.
Depth=0..3, fanout=1..3, seconds=2..300. SIGSTOP/CONT турших бол зөвхөн өөрийн workload-ийн root PID-д дараах дохиог өгнө:
\begin{lstlisting}
kill -STOP ROOT_PID
# Refresh in the UI, then continue:
kill -CONT ROOT_PID
\end{lstlisting}

ROOT\_PID гэдэг үгийн оронд Terminal-д хэвлэгдсэн тоог бичнэ. STOP өгөөд Шинэчлэх дарахад root-ийн төлөв T болж шарлана. CONT өгсний дараа дахин шинэчлэхэд task үргэлжлэн ажиллана. Бусад системийн task-д дохио өгөхгүй.

\section{Үйлдлүүдийг шалгах}
\begin{enumerate}
\item \textbf{LINEAR ба DFS.} Root PID-г цэвэрлэж, DFS сонгоно. Дараах товчоор алхахад эцэг task хүүхдийнхээ өмнө сонгогдоно. Нэг хүүхдийн дэд мод дууссаны дараа дараагийн салаа руу шилжинэ. LINEAR сонгоход жагсаалтын дараалал kernel-ийн шугаман дараалалд шилжинэ; task-ийн PID өөрчлөгдөхгүй.
\item \textbf{Thread шүүлт.} Жишээ 2-ын created snapshot-д Root PID=90 сонгоно. Threads асаалттай үед 7 task, унтраахад 5 process үлдэнэ. PID 95, 96 нь TGID 90-тай нэмэлт thread-үүд юм. Жишээ 3-ын Python workload зөвхөн process үүсгэдэг.
\item \textbf{Хадгалах ба нээх.} Snapshot хадгалах товчоор TSV файл үүсгээд Файл нээхээр дахин сонгоно. PID, parent, төлөв ижил байна. File горим нь өмнөх хэмжилтийг харуулна. Бодит хэмжилтэд буцахдаа цонхоо хааж \code{bash run.sh --kernel} ажиллуулна.
\item \textbf{Буруу оролт.} Root PID-д abc оруулахад алдааны мэдээлэл гарна. Зангилааны хязгаарт 0 оруулахад зөвшөөрөгдөх 1--2000 мужийг мэдээлнэ. Утгыг засаж дахин Хэрэглэх дарна.
\item \textbf{Дуусах ба Reset.} Workload дууссаны дараа Root PID-г цэвэрлэж шинэчилнэ. Үүсгэсэн процессууд жагсаалтаас алга болно. Reset нь харагдацын тохиргоог сэргээнэ; системийн процессыг зогсоохгүй.
\end{enumerate}

\section{Ажиллагааны шалгалт}
\subsection{Үндсэн build ба тест}
\begin{lstlisting}
make -C src/kernel
bash scripts/test.sh
sudo dmesg | grep 'taskgraph LINEAR' | head
sudo dmesg | grep 'taskgraph DFS' | head
ps -el
ps -eLf
cat /proc/taskgraph
\end{lstlisting}
Python тестийн хүлээгдсэн үр дүн нь Linux дээр 23 тест OK. LINEAR log-ийг process leader-уудтай, DFS log-ийг thread-үүдтэй харьцуулна. PID 0 нь \code{init\_task}. Хэмжилтийн агшин өөр учраас түр task, төлөвийн зөрүү гарч болно.
\subsection{Нэмэлт live ба QEMU тест}
\begin{lstlisting}
PYTHONPATH=src python3 scripts/verify_live.py
sudo apt install -y qemu-system-x86 busybox-static
PYTHONPATH=src python3 scripts/qemu_smoke.py \
  --kernel /boot/vmlinuz-$(uname -r)
\end{lstlisting}
Эхний скрипт ачаалсан module дээр 6 live шалгалт хийнэ. Хоёр дахь нь тохирох kernel image, build хийсэн module-оор QEMU дотор 12 шалгалт ажиллуулна. Image нь уншигдах боломжтой байна. Алдаа гарвал exit code 1 буцаана. Туршилтын log, JSON, TSV-г тусад нь хадгална.
